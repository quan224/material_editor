## 一、电脑剖面：从电脑的哪些位置拿了什么

```
┌─────────────────────────── 你的程序（main.exe，CPU 进程）────────────────────────────┐
│                                                                                     │
│  手里的句柄（本质是指针/编号，存在我们自己的内存里）：                                 │
│    instance  surface  debugMessenger  physicalDevice  device  graphicsQueue  presentQueue  swapChain │
│                                                                                     │
└──────┬──────────────────────┬───────────────────────┬────────────────────────────────┘
       │ 所有 vk 调用          │ 消息                  │ 窗口操作
       ▼                      ▼                       ▼
┌───────────────┐   ┌──────────────────┐   ┌──────────────────┐
│ Vulkan loader │   │ 验证层 DLL        │   │ 操作系统 / 窗口系统│
│ vulkan-1.dll  │   │ VkLayer_khronos_  │   │ Win32 + DWM      │
│               │   │ validation.dll    │   │                  │
│ ・VkInstance   │   │                  │   │ ・GLFW window    │
│  在这里开的会话 │   │ ・debugMessenger  │   │ ・surface 的接头  │
│  （装载驱动、   │   │  挂在它的拦截链上  │   │  （窗口的客户区） │
│   转发调用）    │   │                  │   │                  │
└──────┬────────┘   └────────▲─────────┘   └────────▲─────────┘
       │ 装载                          拦截调用         │ 呈现目标
       ▼                                              │
┌──────────────────────────────────┐                  │
│ 显卡驱动 ICD（厂商 DLL）           │                  │
│                                  │                  │
│ ・physicalDevice：它报上来的硬件清单│                  │
│ ・device：跟它开的私有工作连接     │                  │
│ ・图形/呈现能力查询               │                  │
└──────┬───────────────────────────┘                  │
       │ 驱动指挥硬件                                 │
       ▼                                              │
┌──────────────────────────────────┐                  │
│ 显卡 GPU（RTX 4070 Ti SUPER）     │                  │
│                                  │                  │
```

**一句话读图**：程序里的句柄只是"凭证"，真东西分散在电脑四层——**会话在 loader、拦截在验证层、连接在驱动、执行在 GPU、窗口在操作系统**。vk 调用就是拿凭证去对应那层取货/办事。

## 二、对象依赖树（谁生谁）

```
GLFW window                        ← GLFW 的，不是 Vulkan 对象
  │
  └─ VkInstance instance                     [create_instance]
       │  与 Vulkan 的会话：装载驱动 + 启用扩展/验证层
       │
       ├─ VkDebugUtilsMessengerEXT           [setupDebugMessenger]
       │    验证层消息 → debugCallback（仅开发期）
       │
       ├─ VkSurfaceKHR surface               [createSurface]
       │    呈现目标：Vulkan ↔ 窗口的接头
       │
       └─ VkPhysicalDevice physicalDevice    [pickPhysicalDevice]
            │  显卡"说明书"——查询获取，无创建/销毁
            │
            └─ VkDevice device               [createLogicalDevice]
                 │  与这张卡的私有工作连接
                 │
                 ├─ VkQueue graphicsQueue       ┐ 两句柄常相同
                 └─ VkQueue presentQueue        ┘ （图形/呈现可能是同族）
                 │
                 └─ VkSwapchainKHR swapChain   [createSwapchain]
                      │  显示接力池：挂 device（能力）+ surface（去向）两个父
                      │  三方协商出的"怎么换帧"合同（格式/模式/尺寸）
                      │
                      └─ swapChainImages        查询获取（vkGetSwapchainImagesKHR）
                         无创建/销毁，同 physicalDevice             │
```

**销毁顺序 = 从叶到根**（clean_up）：swapChain → device → surface → instance（messenger 在 instance 前）

## 五、一条队列在 GPU 中的调用流程

```
 CPU 侧（你的线程）                          GPU 侧
═════════════════════════════════════════════════════════════════

 ① 录制            ② 提交              ③ 排队      ④ 分发     ⑤ 执行
 ─────────         ─────────           ───────     ───────    ───────
 vkCmdBindPipeline  vkQueueSubmit ───▶ ┌────────┐  调度器     SM 阵列
 vkCmdSetViewport   (队列, 缓冲)       │ 缓冲 A  │  (GPU前端)  (上千核心)
 vkCmdBindVertex      │                │ 缓冲 B  │     │        │
 vkCmdDraw ×100       │                │ 缓冲 C  │     ▼        ▼
 vkCmdEnd             │                └────────┘            画！算！
 ─────────            │                 ↑同队列内            读写显存！
 纯写内存，            │                   提交序=执行序
 不碰 GPU             ▼
                    CPU 立刻返回，
                    该干嘛干嘛（异步）

 ⑥ 完成：GPU 干完 → fence（栅栏）通知 CPU ──▶ CPU 知道"这批画完了"
```

三个关键抽象：

- **录制 ≠ 执行**：`vkCmd*` 不碰 GPU，只是往 `VkCommandBuffer`（一块内存）写待办清单——可以预录反复用、多线程分头录
- **提交是异步交接**：`vkQueueSubmit` 整包递进队列就返回，CPU/GPU 从此并行
- **队列 = 有序传送带**：同队列内提交序 = 执行序（免费）；跨队列无保证（并行换同步）

类比：命令缓冲 = 写好的整张订单，vkQueueSubmit = 订单塞进后厨窗口，队列 = 排队架，GPU = 后厨灶台并行开火，fence = 取餐提醒器。graphicsQueue 就是那个窗口。

## 六、swapchain：FIFO 接力池（我们选了 minImageCount+1 张）

```
        ┌──────────── swapChain（display 接力池）────────────┐
        │                                                    │
        │   [图 A]          [图 B]          [图 C]            │
        │  正在显示         画好了排队        程序正在画         │
        │  ═══════          ──────          ✏️✏️✏️           │
        └────┬─────────────────▲────────────────┬───────────┘
             │                 │                │
        显示控制器          vkQueuePresent     vkAcquireNextImage
        （GPU 往返接         （画完的递进来）    （要画先领一张空的）
          力棒的部分）                            │
             │                                     ▼
        屏幕刷新率 vsync ←────────────── 程序渲染循环（课 14 补全）
```

- **每张图三个状态循环**：被程序画 → 排队等显示 → 正在屏幕上 → 回收复用
- FIFO 模式 = 排队跟随屏幕刷新（vsync）——我们 `chooseSwapPresentMode` 选的它，保证存在
- `imageCount = minImageCount + 1`：在"显示用掉一张"时程序手里还有得画，不空转
- 课 8 的 image views = 给每张图配一个"怎么读它"的取景器；课 14 的绘制循环 = acquire → 画 → present 一圈圈转
