## 窗口（init_window 建的，一切的开始）

```
              800 像素（宽）
   ┌───────────────────────────────────────┐ ─┐
   │ ┌ Vulkan ──────────────────────────□ ✕ │  │  ← 标题栏（操作系统画的）
   │ └─────────────────────────────────────┘  │
   │                                         │  │
   │                                         │  │
   │           客户区 800 × 600               │ 600 像素（高）
   │      （Vulkan 将来画画的地方，            │  │
   │         现在还是黑的）                    │  │
   │                                         │  │
   │                                         │  │
   └───────────────────────────────────────┘ ─┘
    ↑ 边框锁死拖不动            ↑ 客户区尺寸 = 将来交换链图像尺寸
```

```
glfwWindowHint(GLFW_CLIENT_API, GLFW_NO_API);

   GLFW 是 OpenGL 窗口库出身——默认会给每个窗口
   塞一个 OpenGL 上下文（画布的 OpenGL 版本）：

   默认行为：  窗口 + OpenGL 上下文     我们要的：  光秃窗口
             ┌────────┐                          ┌────────┐
             │ 窗口    │                          │ 窗口    │
             │ +GLctx │ ← 多余！我们               │        │
             └────────┐   用 Vulkan               └────────┘
                        NO_API 就是把它关掉


glfwWindowHint(GLFW_RESIZABLE, GLFW_FALSE);

   锁死窗口尺寸，用户拖边框无效。

   为什么锁：交换链图像创建时定格 800×600，
   窗口若被拖成 1000×800：

   ┌───── 1000×800 的窗口 ─────┐
   │ ┌── 800×600 的图像 ──┐     │   图像还是 800×600，
   │ │   △                │     │   填不满窗口 → 变形/黑边
   │ └────────────────────┘     │   （处理办法要等"重建交换链"章）
   └────────────────────────────┘
```
## 验证层 VK_LAYER_KHRONOS_validation（它是什么 + checkValidationLayerSupport 在干什么）

```
━━━━━━━ 它是什么（实物）━━━━━━━

  C:\VulkanSDK\1.4.363.0\Bin\
  │
  └─ VkLayer_khronos_validation.dll   ← 就是它！约 20MB 的 DLL，
      │                                 里面装着几百条 Vulkan 使用规则的
      │                                 检查代码（规范写明"必须这样用"，
      │                                 它逐条对着查）
      │
      └─ DLL 的元数据里登记着：
         名字 = "VK_LAYER_KHRONOS_validation"   ← 我们代码里那个字符串
                                                   就是在指名道姓要它


━━━━━━━ checkValidationLayerSupport 在干什么（两步）━━━━━━━

  第一步：问系统"你机器上装了哪些层？"
  ────────────────────────────────
  vkEnumerateInstanceLayerProperties(&count, nullptr)   ← 数几个（两段式）
  vkEnumerateInstanceLayerProperties(&count, 数组)      ← 拿名单

  枚举出来的本机层名单（= 本机装了哪些层的 DLL）：
  ┌────────────────────────────────────────┐
  │  VK_LAYER_KHRONOS_validation    ← SDK装 │
  │  VK_LAYER_LUNARG_monitor        ← SDK装 │
  │  VK_LAYER_NV_overlay            ← 驱动带 │
  └────────────────────────────────────────┘

  第二步：拿"我要的"逐个去名单里找
  ────────────────────────────────
  我要的（validationLayers 数组）：
      "VK_LAYER_KHRONOS_validation"  → 在名单里 ✓

  全找到 → return true  → 放心启用
  （假设没装 SDK：名单里没有它 → 找不到 → return false
     → create_instance 里 throw "validation layers not available"）
```

一句话：**第一步数的是本机装了哪些 DLL，第二步拿名字去对——对上才敢启用**（启用一个不存在的层，vkCreateInstance 必失败，所以先查后用）。





## CreateInfo 到底在干什么（每次 vkCreate* 的完整过程，通用机制）

```
 你这边（CPU 栈上）                驱动那边（它的内存/显存）
──────────────────────           ─────────────────────────────────

时刻 1：填表（你自己的事，没有任何人参与）
─────────────────────────────────────
VkXxxCreateInfo info{};        ← 这几行只是"在你进程的栈上
info.sType = ...;                写几十字节的内存"，
info.别的 = ...;                 loader/验证层/驱动统统不知道
                                 这张表的存在。填完放一小时也行

时刻 2：交表（vkCreateXxx 这一执行，才开始走链）─────────────
vkCreateXxx(device, &info, ..., &handle);
              ↑
              传的是指针（&info = 你栈上那块内存的地址）
   ┌─────────┴──────────────────────────────────┐
   │ loader 收到这次函数调用                        │
   │   ↓ 验证层拦截：顺着指针扫一遍表内容，查合法性    │
   │   ↓ 驱动收表："读表"就发生在这里——              │
   │      按结构体布局逐字段读你那块栈内存            │
   │      （sType 在偏移 0、下一字段在偏移 8……）     │
   │      按表施工：在驱动内部构造真身——              │
   │      一个 C++ 对象，含你填的全部配置             │
   │      + 内部状态（引用计数、绑定关系…）           │
   │      登记进对象表                              │
   └──────────────────────────────────────────────┘
   ↓ 函数返回，把新对象的编号写回 &handle（=句柄/受理号）

 之后每个调用：
 vkCmdBindPipeline(cmd, handle) ─▶ 驱动拿编号查表 → 找到真身 → 操作它
```

类比：**政府窗口**——CreateInfo 是申请表，验证层是受理窗口查材料齐不齐，驱动是后台按表建档，**句柄是受理号**，后续办事全凭受理号。"管线不可变"= 档案袋建好封死，改任何一项都要重新交表建新档。

## 显卡与队列族（第 4 章 pickPhysicalDevice / findQueueFamilies）

```
━━━ 本机有哪些卡（vkEnumeratePhysicalDevices 枚举出 2 张）━━━

 ┌────────────────────────┐   ┌────────────────────────┐
 │ Intel UHD Graphics 630 │   │ NVIDIA GeForce RTX 5060 │
 │ 核显（CPU 自带）        │   │ 主力卡：显存 8GB         │
 └────────────────────────┘   └────────────────────────┘
   两家驱动（ICD）都被 loader 装载，各报一张；
   isDeviceSuitable 两张都过 → 选先枚举到的
   （教程没打分机制；"优先独显"是可加的打分项）


━━━ 族的数据视图（vkGetPhysicalDeviceQueueFamilyProperties 查回）━━━

  族号   能力 flags（通道权限清单）          通道数 queueCount
  ─────  ──────────────────────────────────  ─────────────
   0     GRAPHICS|COMPUTE|TRANSFER|SPARSE        1   ← 全能主族
   1-8   COMPUTE|TRANSFER|SPARSE                 8   ← 纯算力族
   ...   TRANSFER 专用 / 视频编解码专用 等       …
  共 16 族（NVIDIA 消费卡典型值；精确数跑 vulkaninfo 验证）


━━━ 三个概念别混（flags ≠ queueCount ≠ 引擎）━━━

   flags     = 这条通道允许提交哪些类命令   （窗口的服务清单）
   queueCount = 这个族开放几条通道          （开了几个窗口）
   引擎      = 芯片里的物理资源             （后台的部门）

   族 0：后台所有部门都调得动（四项全能）→ 但只开 1 扇窗口；
   算力族：调不动光栅化那套电路（没有 GRAPHICS 权限）→ 开 8 扇窗


━━━ 族的芯片实物（俯视，出厂焊死：只能查、只能申请，不能造）━━━

  ┌─ GPU 芯片 ─────────────────────────────────────┐
  │ 族 0：图形引擎全套 + 1 条通道                    │
  │  ┌─ 图形引擎内部流水线 ──────────────────────┐  │
  │  │ 顶点缓冲 → ①IA 取顶点拼图元（拓扑配置）     │  │
  │  │   → ②SM 跑顶点 HLSL（可编程）              │  │
  │  │   → ③裁剪/视口单元（六比较裁剪、÷w、视口）  │  │
  │  │   → ④光栅化器（铺片元、面剔除）             │  │
  │  │   → ⑤Early-Z（着色前先测深度丢被挡的）      │  │
  │  │   → ⑥SM 跑片元 HLSL（可编程，旁挂采样器）   │  │
  │  │   → ⑦ROP（深度/模板测试、混合、写显存）     │  │
  │  └────────────────────────────────────────────┘  │
  │ 族 1-8：算力引擎（SM 阵列）×8 + 各 1 条通道       │
  │ 搬运族：DMA 引擎（拷数据，不画画）                │
  │ 编码族：视频编解码专用单元                        │
  └──────────────────────────────────────────────────┘
   第 11 章的八张表 = 给 ①③④⑦ 这些固定电路逐个下配置
```

## 显卡实物（拆掉风扇散热器后，PCB 俯视）

```
              挡板侧（朝机箱外）
   ┌────────────────────────────────────────────────┐──────┐
   │                                                │ HDMI ├ 挡板
   │   [供电堆]         [供电堆]                     │  DP  │ 接口
   │  电容·电感·MOS   电容·电感·MOS                  │      │
   │                                                │      │
   │        ┌────────┐   ┌────────┐                │      │
   │        │ 显存①  │   │ 显存②  │     ← 各 2GB    │      │
   │        │ GDDR7  │   │ GDDR7  │       GDDR7    │      │
   │        └───┬────┘   └────┬───┘                │      │
PCB │            │  焊在板上的 │                    │      │
板  │        ┌───▼────────────▼───┐                │      │
   │        │     GPU 芯片（die）  │   ← 一小片硅，  │      │
   │        │   GB206，几百亿晶体管 │     指甲盖大小  │      │
   │        │                    │                │      │
   │        │  里面：命令处理器/    │                │      │

   │        │ 显存③  │   │ 显存④  │    4 颗合计 8GB │      │
   │        │ GDDR7  │   │ GDDR7  │                │      │
   │        └────────┘   └────────┘                │      │
   │                                                │      │
   │  ═╦╦╦╦╦╦╦╦╦╦╦╦╦╦╦╦╦╦╦╦╦╦╦╦╦═                  │      │

   └────────────────────────────────────────────────┘──────┘
        平时上面盖着：散热器鳍片+热管+两个风扇

 学过的东西住哪颗芯片：
   交换链图像(像素数组)  → 显存①②③④（8GB 分着用）
   图形管线(GPU 机器码)  → 显存
   SM/光栅化器/ROP/队列  → GPU die 里（几十亿晶体管就是它们）
   上屏                  → die 里的显示控制器 → 挡板接口 → 显示器
   CPU 来的命令          → 金手指这条 PCIe 通道进来
   供电堆                → 把电源 12V 降到 die/显存要的低电压
```
