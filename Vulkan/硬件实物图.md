## 验证层 VK_LAYER_KHRONOS_validation（它是什么 + checkValidationLayerSupport 在干什么）

```
━━━━━━━ 它是什么（实物）━━━━━━━

  C:\VulkanSDK\1.4.363.0\Bin\
  │
  └─ VkLayer_khronos_validation.dll   ← 就是它！约 20MB 的 DLL，
      │                                 里面装着几百条 Vulkan 使用规则的
      │                                 检查代码（规范写明"必须这样用"，
      │                                 它逐条对着查）
      │
      └─ DLL 的元数据里登记着：
         名字 = "VK_LAYER_KHRONOS_validation"   ← 我们代码里那个字符串
                                                   就是在指名道姓要它


━━━━━━━ checkValidationLayerSupport 在干什么（两步）━━━━━━━

  第一步：问系统"你机器上装了哪些层？"
  ────────────────────────────────
  vkEnumerateInstanceLayerProperties(&count, nullptr)   ← 数几个（两段式）
  vkEnumerateInstanceLayerProperties(&count, 数组)      ← 拿名单

  枚举出来的本机层名单（= 本机装了哪些层的 DLL）：
  ┌────────────────────────────────────────┐
  │  VK_LAYER_KHRONOS_validation    ← SDK装 │
  │  VK_LAYER_LUNARG_monitor        ← SDK装 │
  │  VK_LAYER_NV_overlay            ← 驱动带 │
  └────────────────────────────────────────┘

  第二步：拿"我要的"逐个去名单里找
  ────────────────────────────────
  我要的（validationLayers 数组）：
      "VK_LAYER_KHRONOS_validation"  → 在名单里 ✓

  全找到 → return true  → 放心启用
  （假设没装 SDK：名单里没有它 → 找不到 → return false
     → create_instance 里 throw "validation layers not available"）
```

一句话：**第一步数的是本机装了哪些 DLL，第二步拿名字去对——对上才敢启用**（启用一个不存在的层，vkCreateInstance 必失败，所以先查后用）。





## CreateInfo 到底在干什么（每次 vkCreate* 的完整过程，通用机制）

```
 你这边（CPU 栈上）                驱动那边（它的内存/显存）
──────────────────────           ─────────────────────────────────

时刻 1：填表（你自己的事，没有任何人参与）
─────────────────────────────────────
VkXxxCreateInfo info{};        ← 这几行只是"在你进程的栈上
info.sType = ...;                写几十字节的内存"，
info.别的 = ...;                 loader/验证层/驱动统统不知道
                                 这张表的存在。填完放一小时也行

时刻 2：交表（vkCreateXxx 这一执行，才开始走链）─────────────
vkCreateXxx(device, &info, ..., &handle);
              ↑
              传的是指针（&info = 你栈上那块内存的地址）
   ┌─────────┴──────────────────────────────────┐
   │ loader 收到这次函数调用                        │
   │   ↓ 验证层拦截：顺着指针扫一遍表内容，查合法性    │
   │   ↓ 驱动收表："读表"就发生在这里——              │
   │      按结构体布局逐字段读你那块栈内存            │
   │      （sType 在偏移 0、下一字段在偏移 8……）     │
   │      按表施工：在驱动内部构造真身——              │
   │      一个 C++ 对象，含你填的全部配置             │
   │      + 内部状态（引用计数、绑定关系…）           │
   │      登记进对象表                              │
   └──────────────────────────────────────────────┘
   ↓ 函数返回，把新对象的编号写回 &handle（=句柄/受理号）

 之后每个调用：
 vkCmdBindPipeline(cmd, handle) ─▶ 驱动拿编号查表 → 找到真身 → 操作它
```

类比：**政府窗口**——CreateInfo 是申请表，验证层是受理窗口查材料齐不齐，驱动是后台按表建档，**句柄是受理号**，后续办事全凭受理号。"管线不可变"= 档案袋建好封死，改任何一项都要重新交表建新档。

## 显卡与队列族（第 4 章 pickPhysicalDevice / findQueueFamilies）

```
━━━ 本机有哪些卡（vkEnumeratePhysicalDevices 枚举出 2 张）━━━

 ┌────────────────────────┐   ┌────────────────────────┐
 │ Intel UHD Graphics 630 │   │ NVIDIA GeForce RTX 5060 │
 │ 核显（CPU 自带）        │   │ 主力卡：显存 8GB         │
 └────────────────────────┘   └────────────────────────┘
   两家驱动（ICD）都被 loader 装载，各报一张；
   isDeviceSuitable 两张都过 → 选先枚举到的
   （教程没打分机制；"优先独显"是可加的打分项）


━━━ 族的数据视图（vkGetPhysicalDeviceQueueFamilyProperties 查回）━━━

  族号   能力 flags（通道权限清单）          通道数 queueCount
  ─────  ──────────────────────────────────  ─────────────
   0     GRAPHICS|COMPUTE|TRANSFER|SPARSE        1   ← 全能主族
   1-8   COMPUTE|TRANSFER|SPARSE                 8   ← 纯算力族
   ...   TRANSFER 专用 / 视频编解码专用 等       …
  共 16 族（NVIDIA 消费卡典型值；精确数跑 vulkaninfo 验证）


━━━ 三个概念别混（flags ≠ queueCount ≠ 引擎）━━━

   flags     = 这条通道允许提交哪些类命令   （窗口的服务清单）
   queueCount = 这个族开放几条通道          （开了几个窗口）
   引擎      = 芯片里的物理资源             （后台的部门）

   族 0：后台所有部门都调得动（四项全能）→ 但只开 1 扇窗口；
   算力族：调不动光栅化那套电路（没有 GRAPHICS 权限）→ 开 8 扇窗


━━━ 族的芯片实物（俯视，出厂焊死：只能查、只能申请，不能造）━━━

  ┌─ GPU 芯片 ─────────────────────────────────────┐
  │ 族 0：图形引擎全套 + 1 条通道                    │
  │  ┌─ 图形引擎内部流水线 ──────────────────────┐  │
  │  │ 顶点缓冲 → ①IA 取顶点拼图元（拓扑配置）     │  │
  │  │   → ②SM 跑顶点 HLSL（可编程）              │  │
  │  │   → ③裁剪/视口单元（六比较裁剪、÷w、视口）  │  │
  │  │   → ④光栅化器（铺片元、面剔除）             │  │
  │  │   → ⑤Early-Z（着色前先测深度丢被挡的）      │  │
  │  │   → ⑥SM 跑片元 HLSL（可编程，旁挂采样器）   │  │
  │  │   → ⑦ROP（深度/模板测试、混合、写显存）     │  │
  │  └────────────────────────────────────────────┘  │
  │ 族 1-8：算力引擎（SM 阵列）×8 + 各 1 条通道       │
  │ 搬运族：DMA 引擎（拷数据，不画画）                │
  │ 编码族：视频编解码专用单元                        │
  └──────────────────────────────────────────────────┘
   第 11 章的八张表 = 给 ①③④⑦ 这些固定电路逐个下配置
```

 硬件实体之一；纹理采样器是片元着色器旁挂的那个；ROP 是第 11 章
 颜色混合+深度测试伪代码的硬件执行处；命令处理器消化命令缓冲。
 GPC（Graphics Processing Cluster）= SM 打包单位，各带一份光栅引擎。

## die 各分区的作用（逐个是什么、干什么）

```
 层级：die ⊃ GPC ⊃ SM ⊃ 着色器核心

 GPC（Graphics Processing Cluster，图形处理簇）
   = SM 的打包单位：十几个 SM + 1 个光栅引擎 + 配套电路。
     厂商也按 GPC 数量切型号：同 die 封 5 个是 5070、4 个是 5060。
 PHY（physical layer，物理层电路）
   = 芯片里管实际电信号收发的接口电路：把内部 0/1 变成
     高速电信号打上走线、再收回对面的信号还原成 0/1。
     显存 PHY 贴 die 边缘（引脚要出芯片连显存颗粒）。
 SM（Streaming Multiprocessor，流式多处理器）
   = 计算的最小重复单元，图上画成小方格（"格子"即 SM），
     你的每条 HLSL 指令都在格子里的核心上执行。
```

| 分区 | 是什么 | 干什么 / 对应已学 |
|------|--------|------------------|
| GPC | SM 打包成的簇 | 调度和布线的模块单位，各带一份光栅引擎 |
| SM | 计算最小重复单元 | 跑 HLSL；图形族/算力族共用的公共池 |
| 着色器核心 | SM 内 ×128，分 4 组 | 执行指令的 ALU——顶点/片元着色就在这跑 |
| 寄存器文件 | SM 私有的快速存储 | 着色器变量住的地方（属性槽格子的硬件实体之一） |
| L1 缓存 | SM 私有缓存 | 给本 SM 的核心喂近期用过的数据 |
| L2 缓存 | 全 die 共享的大缓存（横贯中部） | 所有模块的数据中转站，去显存前的最后一站 |
| 纹理采样器 | SM 内专用电路（TMU） | 读纹理、过滤插值（纹理章的主角） |
| 光栅引擎 | 每个 GPC 一份的固定电路 | 三角形铺片元、面剔除（第 11 章光栅化器配置的执行处） |
| ROP 分区 | die 边缘的输出单元 | 深度/模板测试、颜色混合、写显存（第 11 章两张表的执行处） |
| 拷贝引擎（DMA） | 独立搬运电路 | CPU↔显存、显存↔显存 拷数据，不占 SM（搬运族的硬件） |
| 视频引擎 | NVENC 编码 / NVDEC 解码 | 视频硬解硬编（看视频不占 CPU 就是它） |
| 显存 PHY | die 边缘接口电路 ×4 | 对 4 颗 GDDR7 收发电信号（每秒几十 GB 的门户） |
| PCIe 控制器 | 对主板方向的接口 | CPU 的命令/数据从这里进出（金手指那头） |
| 显示控制器 | 输出电路 | 每 16.7ms 扫一张图 → 挡板接口 → 屏幕 |
| 命令处理器/调度器 | die 前端 | 从队列取命令缓冲、拆解、派活给各模块（分发任务的人，无族归属） |
| 互连网络 | 横贯中部的走线网 | 各模块互相传数据的"内部高速公路" |

## 族、逻辑设备与硬件的关系（三层分清）

```
━━━ 族 = 驱动登记条目（不是硬件），声明权限 ━━━

die 上的硬件分区                     驱动里的族登记（谁能调谁）
────────────────────────           ──────────────────────────
命令处理器（前端，派活的） ◀──────── 所有族的命令都先到这
SM 阵列（公共池）        ◀──────── 图形族 ✓  算力族 ✓（共享同一批）
光栅引擎 + ROP           ◀──────── 仅图形族 ✓
拷贝引擎（DMA）           ◀──────── 图形族 ✓  算力族 ✓  搬运族 ✓
视频引擎                  ◀──────── 仅编解码族 ✓

 通道也不是独立硬件：队列 = 命令处理器前端的"命令接收入口"，
 queueCount=1 即开 1 个入口。命令进处理器后由调度器拆开、
 按类型派给对应分区——图形命令走 SM→光栅→ROP 全链，
 搬运命令直派 DMA。


━━━ 逻辑设备 VkDevice = 你的程序在这张卡上的专属配置 ━━━

硬件（唯一的物理事实）          驱动内存里的对象（每个程序各一份）
─────────────────────         ─────────────────────────────────
RTX 5060 这张卡     ◀────────  你的 VkDevice：
                                · 你申请的队列入口（族0的0号通道）
                                · 你启用的扩展/特性记录
                                · 你的显存分配记账
                              别的程序的 VkDevice：另一份同款配置

 类比：physicalDevice = 健身房（硬件只有一栋）；
      VkDevice = 你办的会员卡——登记用哪些器械（队列）、
      开哪些项目（扩展）。多个程序同时用 GPU（你的渲染 +
      桌面合成 + 浏览器视频），各家一个 device，命令最终
      都汇进同一批硬件通道，驱动交错调度——GPU"同时"跑
      N 个程序靠的就是这层虚拟化。


━━━ 三层关系一句话 ━━━

 硬件分区（物理事实）
   → 族（驱动登记的权限分组：哪条通道能调哪些分区）
     → 逻辑设备（你的程序在这张卡上的专属配置 + 队列引用）

 后两层都是软件对象，住驱动内存里；你手里只攥着它们的编号（句柄）。
```
