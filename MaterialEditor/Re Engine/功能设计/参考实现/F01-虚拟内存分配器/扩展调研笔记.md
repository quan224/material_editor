# F01 扩展调研笔记 — GPU 显存分配（生产级做法 + 坑）

> 补足参考实现（空闲链表+合并+placed+上传环）之外的生产级知识。均来自一手机密源。

## 关键发现（超出基础实现的硬货）

### 1. OffsetAllocator 为什么 O(1) + 低碎片
- **256 个 size bin，容量按 8 位浮点分布**（3 位尾数 + 5 位指数），不是 2 的幂 → 最坏内部碎片 **+12.5%**（2 的幂会浪费 +100%）。
- 两级位图（类 TLSF）+ **2 条 LZCNT 指令**定位下一个可用 bin → allocate/free 与堆大小无关的常数时间。
- 纯偏移分配器（只返回 offset，元数据与资源分离），天然适合子分配 GPU heap。
- 我的空闲链表 first-fit 是 O(n)，长跑后碎片累积 → **这是替换的最大动机**。
- 来源：https://github.com/sebbbi/OffsetAllocator ｜ TLSF 论文 http://www.gii.upv.es/tlsf/files/papers/ecrts04_tlsf.pdf

### 2. VMA（Vulkan 标杆）怎么做的
- 每种 memory type 维护一组 **256MB 大块**，块内**空闲链表 best-fit**。
- 三算法可选：默认（free-list best-fit）/ **Buddy**（2 的幂切分，适合等大池）/ **Linear**（stack/double-stack/ring，free-at-once，最快）。
- **Defragmentation 是显式 pass 化的**：VMA 只算"搬哪些 allocation"，应用自己发 copy 命令、等完成、再 end pass 让 VMA 回收源。可 `maxBytesPerPass` 分帧增量避免 hitch。
- 来源：https://gpuopen-librariesandsdks.github.io/VulkanMemoryAllocator/html/defragmentation.html

### 3. D3D12 资源类型与对齐（固定常量，记住）
- **Committed**（资源+隐式 heap，最简单，NVIDIA 推荐优先）/ **Placed**（自建 heap+offset，须处理对齐和 aliasing barrier）/ **Reserved**（tiled，64KB tile，部分支持）。
- **对齐**：buffer/普通纹理 **64KB**，MSAA **4MB**；普通纹理 ≤64KB 可申请 **4KB** small 对齐（UNKNOWN layout、非 RT/DS、要主动填 Alignment 字段）。
- **Tight Alignment**（Agility SDK 1.716+）：placed buffer 可降到 **8B–256B**——大量小 buffer 省内存巨大。
- **驻留**：budget 用 `IDXGIAdapter3::QueryVideoMemoryInfo` 查，超 budget 进程被 OS 冻结；**销毁比 Evict 更可靠**（GPU VA 接近 budget 时 Evict 失效）。
- 来源：https://microsoft.github.io/DirectX-Specs/d3d/D3D12TightPlacedResourceAlignment.html ｜ https://asawicki.info/news_1726_secrets_of_direct3d_12_resource_alignment

### 4. Descriptor 策略
- **双堆 + copy 模型**：非 shader-visible staging 堆（无上限）建描述符 → shader-visible 堆（CBV_SRV_UAV **≤1,000,000**，Sampler **≤2,048**）用 `CopyDescriptors` 拷过去。
- 单描述符大小 ≤64B，**必须运行期 `GetDescriptorHandleIncrementSize` 查，禁硬编码**。
- **Bindless**：`Texture2D tex[]`（unbounded）+ root signature range `NumDescriptors=-1`（只能最后一个 range）；divergent 索引必须 `NonUniformResourceIndex(i)`。
- **坑**：shader-visible heap 在很多系统只有 **~96MB CPU-visible vidmem**，几个大堆会撑爆被降级到 sysmem。
- 来源：https://microsoft.github.io/DirectX-Specs/d3d/ResourceBinding.html

### 5. 上传缓冲
- **Constant buffer 强制 256B 对齐 + 最小 256B**（`D3D12_CONSTANT_BUFFER_DATA_PLACEMENT_ALIGNMENT`）——通用 alloc 里最容易漏这条。
- 大 upload buffer **一次性 Map 永久保持**（readRange={0,0}）。
- 纹理上传**必须**走 `GetCopyableFootprints`，紧密 packed 会错位。
- 来源：https://learn.microsoft.com/en-us/windows/win32/direct3d12/uploading-resources

## 对我参考实现的具体改进（按性价比）

| 优先级 | 改进 | 收益 |
|---|---|---|
| ★★★ | **空闲链表 → OffsetAllocator/TLSF 位图 bin** | O(1) + 最坏碎片从 +100% 降到 +12.5% |
| ★★★ | **按对齐/用途分堆**（Default-64KB / Default-4MB-MSAA / Upload-64KB），别一个堆吃所有 | 避免 4MB 对齐污染小资源 |
| ★★ | upload ring 的 CB 强制 256B 对齐 + 纹理走 `GetCopyableFootprints` | 修最常见数据错位 bug |
| ★★ | descriptor 改双堆 + 每帧环形切片（取代 per-draw 改描述符） | 绑定不 idle GPU |
| ★ | residency 预算感知（`QueryVideoMemoryInfo` + 主动 evict/销毁低优先级） | 避免 OS 冻结 hitch |
| ★ | 切 **Enhanced Barriers** + placed resource 复用发 aliasing barrier+DISCARD | 修 placed 损坏最隐蔽源 |
| ★（进阶） | 探测启用 Tight Alignment（8B–256B）/ GPU_UPLOAD heap（Win11+ReBAR） | 省大量小 buffer 内存 |
