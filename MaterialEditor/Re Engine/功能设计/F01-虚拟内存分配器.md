# F01 — 虚拟内存分配器（渲染器显存基建）

> 渲染器的 GPU 显存基建：子分配器管 upload buffer、descriptor heap、大块资源（RT 加速结构、meshlet buffer、texture streaming）。
> 类别：B 引擎工程。**执行序第 1**：渲染器一上手就铺；被 F02/F04/F08 依赖。

## 1. 目标与动机

**变成什么功能**：一套 GPU 显存 + descriptor 子分配器，取代裸 `CreateCommittedResource`，统一管渲染器所有 GPU 资源。

**为什么不是 toy**：
- **DX12 必须显式管显存**。没有分配器，每个资源都 `CreateCommittedResource`——慢、碎片化、显存不可控。
- 它是**渲染器基建**：F04 的 RT 加速结构（大块）、F08 的 meshlet/indirect buffer、F02 的显存统计都依赖它。
- RE Engine 专门有一场讲自研虚拟内存分配器的演进——真引擎的必修基建。

## 3. 架构改动（逐层）

**GPU 显存分配**
- **放置式分配**（`CreatePlacedResource`）+ 大块 committed 池：先 reserve 大堆，再子分配 offset。
- **子分配器**：offset-allocator（Garlic 开源）或 TLSF 风格，管 offset 分配/释放，处理对齐与碎片。
- **residency 跟踪**：哪些资源常驻、哪些可淘汰（texture streaming 时用）。
- **aliasing**（进阶）：同生命周期不重叠的资源复用同一段显存。

**Descriptor 分配**
- descriptor heap 子分配：CPU 可见堆（CBV/SRV/UAV）+ GPU 可见堆，copy 桥接；按 offset 线性子分配。

**Upload ring**
- 每帧 upload ring buffer：CPU 写 → GPU 读的数据上传通道，避免每帧新分配。

## 5. 里程碑

- **M1 放置式池 + offset 子分配**：取代裸 committed，能分配/释放 buffer 与 texture。
- **M2 descriptor heap 子分配**：CBV/SRV/UAV 统一管。
- **M3 upload ring**：每帧数据上传走 ring。
- **M4 aliasing / residency**（进阶）：复用显存 + 贴图流送驻留。

## 6. 验收标准

- 分配/释放压力测试不漏不碎（长时间运行显存稳定）。
- **Profiler（F02）能显示显存占用**——这是它可观测的验收。
- F04 的 RT AS 大块、F08 的 meshlet buffer 走它分配，不报 OOM/碎片。

## 7. 诚实说明

- **"看不见但必需"的基建**，没有炫酷效果，但是地基。
- **越早铺越好**：课 14-16 渲染器一上手就做简单版（M1），别等项目大了再重构——那时改造成本极高。
- 不追求 RE Engine 级完整；M1+M2 已能满足本项目，M4 是锦上添花。
