## 1. 引擎架构 / postmortem

**已知：** RE ENGINE（"Reach for the Moon Engine"）2014 年专为《生化危机 7》创建，取代 MT Framework。弃用 MT Framework 是因其工具链慢、不适合 VR/次世代；也拒绝第三方引擎路线（"太通用"）。最初为线性封闭场景恐怖游戏 + 摄影测量/VR 设计。2017 起成为唯一内产引擎，全社共用。游戏逻辑用 **C#** 跑在自研 **REVM** 虚拟机上（从 C#7.3/.NET FW4.8 迁到 C#8.0/.NET）。2023-10 宣布 **"Codename REX"**（RE neXt ENGINE）—— 把新技术渐进整合进现有引擎而非替换。

## 3. 全局光照 / 光照

**已知：** RE ENGINE 是 **Clustered Deferred** 渲染器，用基于 compute 的光剔除体积（32×80×32 R32_UINT 3D 贴图），支撑 RE2/3/Village 房间式设计的密集 punctual/area 光与 PSVR 性能目标。静态/漫射 GI 在专用 compute pass 里从 light-probe 四面体 + IBL cubemap 算出，产出独立的 GI Diffuse 与 GI Specular 屏幕缓冲。方向光用 **SDSM（Sample Distribution Shadow Maps）** 3 级联。PS5/Xbox Series（DMC5 SE、Village 次世代补丁）加入硬件**光追 GI/反射**选项；最新作（Requiem、PRAGMATA）走向 **ReSTIR GI 的全路径追踪**。荒野引入新的动态 GI「DPGI（Dynamic Probe GI）」应对时间/天气变化。

## 4. 抗锯齿（TAA）

**已知：** 提供 TAA、FXAA、TAA+FXAA、SMAA、MSAA、Off。TAA pass 与 FXAA 同在一个 fragment shader 里跑，消费 5 个输入：当前 HDR、上一帧 HDR（已平滑）、速度缓冲（VelocityXYAoSss GBuffer 的 R/G）、深度（给 FXAA）、effect mask（通常排除粒子）。TAA 常量与 tonemap 共用同一 struct（`AABlend`/`AASubPixel`/`ResponsiveAARate`/`sharpness`）。TAA 后强制施加 AMD **CAS** 锐化（不可关）——玩家长期抱怨过锐/发软的根源。早先的填速度 pass 同时喂 TAA 与 motion blur。

## 5. 屏幕空间反射（SSR）/ 反射

**已知：** 用 **Hi-Z Screen-Space Cone-Traced Reflections**（Yasin Uludog 的 HI-Z cone-tracing）。该 pass 有条件触发——按区域的 "SSR volumes" 门控（PWYNO 哲学：只在有反射面的地方追）。管线：从线性深度建 7-mip Hi-Z 缓冲→每 mip 小范围漫射过滤→两次 indirect-dispatch 的光线追迹对 Hi-Z 做 cone-trace→resolve 进新的 "GIR"（GI Reflections）目标，与上帧 GIR 混合做时序稳定。已知局限：无法反射屏外数据→可见的屏幕边缘伪影（长期社区槽点）。Village 次世代补丁加了可选**光追反射**；Requiem/PRAGMATA 用路径追踪反射完全替代 SSR。

**来源：**
- Behind the Pretty Frames: Resident Evil（"HI-Z Tracing" 与完整 "SSR" 章节，7 步管线 + `SSRControl`/`CBHiZ`/`CBResolve`/`FrustumVolume` 结构）：https://mamoniem.com/behind-the-pretty-frames-resident-evil/
- Village RT 反射（WCCFTech）：https://wccftech.com/resident-evil-village-ray-tracing-impact-explored/

## 6. 角色渲染 / 皮肤（SSS）/ 眼睛

**已知：** 皮肤用 **Separable SSSS（FastScreenSpaceSubsurfaceScattering）**——compute pass 先把 SSS mask 写进 `VelocityXYAoSss` GBuffer 目标的 A 通道（B 是 AO、RG 是速度），然后 "Fast SSSSS Apply" 在延迟光照后用 `SubSurfaceParam` 缓冲散射漫射光。角色 GPU 蒙皮（`cbCSSkinning` compute 蒙皮 pass + 面部 blend-shape pass）；Leon 头 54,348 顶点、眼 10,320——RE Engine 角色密度典型。眼睛/手等用独立 GPU 蒙皮顶点布局。路径追踪分支（Requiem/PRAGMATA）角色光照改善最显著——直接光路径追踪带来有体积感的阴影与间接弹射。

**来源：**

## 8. 阴影

**已知：** **级联阴影图（3 级联）** + **SDSM（Sample Distribution Shadow Maps）**——`SDSMEnable`/`SDSMDebugDraw` 标志与 `Cascade_Translate1/2/3` + `Cascade_Bias1/2/3` 字段都在 LightInfo 常量缓冲里明确存在。阴影 pass 有两点特别：(1) 完全由 **indirect drawing**（ExecuteIndirect）驱动；(2) 阴影存在固定 **2048×2048×32 R32_TYPELESS 3D 贴图**（32 slice）而非扁平 atlas——每光/视图一个 slice。多数玩法帧只用一次阴影 pass；过场偶尔 2–3 次。静态阴影图与 IES 光表（1D，512×64）喂延迟光照与体积光柱 pass。路径追踪分支里**阴影图被路径追踪直接光替代**，并配自研轻量 **ScreenSpaceAlphaTest** 让 cutout/AlphaTest 几何（植被、栅栏）在路径追踪下也投软阴影而无需逐 hit 采样纹理。

**来源：**
- Behind the Pretty Frames（"Shadow Pass[es]"、LightInfo struct 含 SDSM + 级联字段、IES 光表）：https://mamoniem.com/behind-the-pretty-frames-resident-evil/

## 9. 后处理 / 调色 / tone mapping

**已知：** 深 compute 后处理栈，强 "Process What You Need ONLY"（PWYNO）哲学——不需要的 pass 整个跳过（如玩法中无 DOF，仅过场启用）。管线：motion blur（compute tilemax + neighbor-max + apply）→ bokeh DOF → 软 bloom（14 步金字塔）→ 合并的 **"LDR PostProcess With Tonemap"** shader（Panini 投影、径向模糊、胶片颗粒、调色、CVD 表、color levels、暗角（Camera Kerare / ケラレ）、tone mapping（filmic ACES-like，`contrast`/`linearBegin`/`linearLength`/`toe`）、镜头畸变）——全部由 **3 个 32×32×32 RGBA8 LUT** 喂。自动曝光用**矩阵/多区域测光** mask（"Hitogram Adjustment"——这个 typo 在正式代码里）。AMD FidelityFX 以"购物车"方式集成：**FSR 1**、**CAS**（常开、隐藏、在 FSR 后强制施加）、**CACAO**（与 SSAO/HBAO+ 并列的 AO 选项）。RE:2023 "HDR Grading" 场讲从 SDR 迁到 **OpenColorIO 的 HDR grading**。

## 12. 流式 / 开放世界（龙信 2、荒野）

## 13. 动画 / 动捕管线

**已知：** RE Engine 动画栈是其最被记录的领域之一，得益于卡普空自家的 RE:2019 与 RE:2023 大会视频。核心系统：**模块化绑定**（"Synchronization Modular Rigging"）、**motion matching**（移动/混合）、**程序化动画**、**动作 retarget**（RE2 组技大量使用）、以及 DMC5 上演示的 GPU 驱动破坏 + 二级动画仿真管线。2023 引入 **"RE Preview"**——直接在 RE Engine 里跑的实时动捕预览系统，来自新开的内产 Creative Studio，支持全表演捕捉与游戏内环境拍摄 + additive 混合关节动画。头发与布料物理用 strand physics 系统（见主题 7）与统一的角色配件碰撞形系统。
