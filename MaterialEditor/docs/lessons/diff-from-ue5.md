# 与 UE5 的设计差异清单

本文档记录项目中为了教学简化而与 UE5 实际实现不同的地方。按模块分类。

---

## 1. 类型系统（课3、课5）

| 方面 | UE5 | 我们 |
|------|-----|------|
| 值类型数量 | `EMaterialValueType` 约 40 种（Float1~4, Double1~4, Int1~4, Bool, Texture2D/3D/Cube, 结构体等） | 仅 Float1~4 四种 |
| 隐式转换规则 | 多层规则：Double↔Float、矩阵衰减、向量扩展等 | 仅 Float1→FloatN |
| 类型推导 | `GetArithmeticResultType` 处理 Double、矩阵等 | 只处理 Float 系列 |
| 位标志用法 | 更复杂的位运算组合 | `1 << n` 简单位标志 |

**为什么这样简化**：Float1~4 覆盖了材质编辑器 90% 的使用场景。Double 和 Int 类型在教学中不常遇到，加进来会增加类型推导的复杂度但不增加核心概念的理解。

---

## 2. 序列化格式（课18）

| 方面 | UE5 | 我们 |
|------|-----|------|
| 存储格式 | `.uasset` 二进制序列化（UObject 的 `Serialize()` 方法） | JSON 文本格式 |
| 引用方式 | 内部 GUID + 对象路径系统 | 用引脚名称（非 ID）存储连接 |
| 资源引用 | 完整的 `FSoftObjectPath` / `FHardObjectPath` 跨文件引用 | 无跨文件引用 |

**为什么这样简化**：二进制序列化需要实现完整的读写框架（UE5 用了整个 `FArchive` 体系）。JSON 格式人类可读，调试方便，用 `nlohmann/json` 几行就能实现。引脚名称比 ID 稳定，重载后不会失效。

---

## 3. 节点创建方式（课4）

| 方面 | UE5 | 我们 |
|------|-----|------|
| 引脚创建位置 | 每个 `UMaterialExpression` 子类在构造函数中调 `CreatePin()` | NodeFactory 工厂方法集中注册 |
| 反射系统 | 完整的 UObject 反射，属性自动暴露给编辑器 | 简化版反射（课5），宏 + offsetof + 模板偏特化 |
| 节点元数据 | 通过 UClass 系统获取（类别、图标、文档等） | 手动在 Expression 子类中返回字符串 |

**为什么这样简化**：UE5 的反射系统（UObject/UClass/UProperty）是整个引擎的基础设施，几千行代码。课5 提供了一个精简版（约 300 行）：用 `ME_FIELD` 宏标记字段，编译期注册到 `ClassDesc`，模板偏特化提供类型安全的读写。覆盖了 90% 的属性暴露需求，同时是 C++ 高级特性（offsetof / 模板偏特化 / if constexpr / 函数指针类型擦除）的实战教材。课7、课18、课20 都给出了反射版的对比示例，但**手写 JSON 路径完全保留**，两种风格可以混用。

---

## 4. 编译器（课6）

| 方面 | UE5 | 我们 |
|------|-----|------|
| 代码规模 | `FHLSLMaterialTranslator` 几千行 | 简化版几百行 |
| 常数折叠 | 多种数学优化（向量运算折叠、矩阵简化、三角函数预计算等） | 仅乘1直通、乘0归零 |
| 代码块去重 | 完整的哈希去重系统，相同表达式只编译一次 | 基础实现 |
| 错误恢复 | 遇错后尝试继续编译其他分支 | 遇错直接停止 |
| 平台特定代码 | 根据目标平台（SM5/ES3.1/Vulkan等）生成不同代码 | 仅 DX12 SM5.0 |

**为什么这样简化**：编译器的核心架构（CodeChunk → 代码生成 → 模板注入）和 UE5 一致，保证了学习目标。优化和平台适配属于工程完善，不影响对编译管线的理解。

---

## 5. DX12 渲染（课14-17）

| 方面 | UE5 | 我们 |
|------|-----|------|
| API 抽象 | RHI（Render Hardware Interface）屏蔽 DX11/DX12/Vulkan/Metal 差异 | 直接使用 DX12 API，无抽象层 |
| 根签名 | 自动从着色器反射生成 | 手动创建 |
| PSO | 有缓存系统，延迟创建，按需编译 | 直接创建 |
| 着色器编译 | 多线程离线编译管线，支持 SM6.0+ | 运行时 `D3DCompileFromFile`，SM5.0 |
| 资源上传 | 专用上传队列和分配器（`FD3D12ResourceUploadBatch`） | 临时命令列表 |
| 资源管理 | `FD3D12ResidencyManager` 自动管理显存驻留 | 无显存管理 |
| 描述符管理 | `FD3D12DescriptorCache` 缓存描述符 | 直接创建 |
| 多线程渲染 | 完整的多命令列表并行录制 | 单线程 |

**为什么这样简化**：RHI 层在 UE5 中约几万行代码，目的是跨平台。我们只用 DX12 一个后端，直接调 API 更直观。PSO 缓存、描述符管理等属于运行时优化，教学重点是理解 DX12 管线流程本身。

---

## 6. 表达式数量（课7、课20）

| 方面 | UE5 | 我们 |
|------|-----|------|
| 内置表达式总数 | ~150 种 | 课7 实现 10 个基础数学/常量，课20 扩展后约 15-20 个 |
| 纹理相关 | TextureSample, TextureObject, TextureCoordinate, TexCoordScaler 等 | TextureSample + TextureCoordinate 各一个 |
| 工具类 | WorldPosition, CameraVector, Fresnel, Noise, PerlinNoise 等 | 少量 |
| 参数类 | ScalarParameter, VectorParameter, TextureParameter, StaticSwitch 等 | ScalarParameter + VectorParameter |
| 自定义 | 完整的 Custom 表达式（支持 HLSL 代码注入） | 无 |

**为什么这样简化**：所有表达式遵循完全相同的模式（继承 Expression → 实现引脚布局 → 实现 Compile），学会 10 个后其余只是数学函数的翻译。

---

## 7. UI 框架（课10-13）

| 方面 | UE5 | 我们 |
|------|-----|------|
| UI 框架 | Slate（UE5 自研声明式 UI 框架） | Qt Widgets（QGraphicsView + QDockWidget） |
| 节点样式 | `SGraphNode` 丰富的主题/皮肤系统，支持缩放、迷你地图等 | 简单的 Qt 自绘（QGraphicsItem） |
| 连接线绘制 | 贝塞尔曲线 + 多种样式（数据线/执行线/动画线） | 基础贝塞尔曲线 |
| 右键菜单 | 完整的搜索/分类/收藏/最近使用 | 基础分类列表 |
| 拖拽连接 | 支持拖出时自动创建类型兼容的节点 | 基础拖拽连接 |

**为什么这样简化**：Slate 是 UE5 独有的 UI 框架，脱离 UE5 无法使用。Qt 是独立第三方库，学到的知识可直接复用到其他项目。

---

## 8. 错误反馈（课19）

| 方面 | UE5 | 我们 |
|------|-----|------|
| 错误显示方式 | 节点标题栏变红 + 独立错误面板 + 点击定位 + 错误日志文件 | 状态栏显示 + 代码面板标红 + 节点高亮 |
| 编译统计 | 显示指令数、临时寄存器数、纹理采样次数等 | 无 |
| 着色器复杂性警告 | 超过阈值时警告（如指令数 > 256） | 无 |

**为什么这样简化**：核心功能（出错时定位到节点）一致。编译统计属于性能分析工具，不影响编译管线本身。

---

## 9. 教学中未实现的功能

以下是 UE5 材质编辑器有但我们完全不做的功能：

| 功能 | UE5 有 | 说明 |
|------|--------|------|
| 材质实例化 | Material Instance（动态参数热更新，不重编译） | 属于运行时优化，编辑器核心用不到 |
| 多 Pass 渲染 | Depth Pass、Shadow Pass、Base Pass、Translucency Pass 等 | 我们只做单次前向渲染预览 |
| 材质函数 | Material Function（可复用的子图） | 类似函数调用，增加编译器复杂度但对核心概念帮助不大 |
| 材质分层 | Material Layer（材质层叠混合） | UE5 新特性，依赖 RDG（Render Dependency Graph） |
| Shader Permutation | 根据编译开关生成数百个着色器变体 | 属于引擎级优化 |
| 虚拟纹理 | Virtual Texturing 支持 | 需要完整的 VT 系统 |
| 异步编译 | 后台线程编译，不阻塞 UI | 教学项目规模小，同步编译足够 |

---

## 总结

简化的核心原则：**保持架构一致，缩小实现规模。**

```
相同点（架构）                    不同点（规模）
─────────────────────           ─────────────────────
Graph → Node → Pin 模型          类型只有 Float1~4
编译器 CodeChunk 体系             表达式 ~20 种 vs ~150 种
拓扑排序 + 反向遍历编译            序列化用 JSON 而非二进制
HLSL 模板注入生成着色器            无 RHI 抽象层，直接 DX12
PBR 材质属性输出                  无材质实例化/多 Pass
信号槽驱动的 UI 更新              Qt 而非 Slate
```

学完这个项目后，看 UE5 材质系统的源码不会有架构层面的陌生感——区别只是"这个模块 UE5 写得更完整"，而不是"这完全是另一种设计"。
