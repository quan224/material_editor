# 写代码技能

## 规则 1：先查 UE，切勿自己乱编

写任何函数/类/算法之前，**先在本地 UE 源码找现成写法**（`D:/material_editor/UE5/UnrealEngine-release/Engine/`）。找到了就逐行对照抄结构，只做教学版命名替换。

- 教案里写了行号的（如「对照 .cpp:4240」）→ 改之前**必须 sed 读原文**，禁止凭印象写
- 找不到完全对应的 → 找最接近的 UE 模式，说明差异在哪，再写
- 历史事故：LWC 算术规则两版全错，就是因为行号写在教案里却没去读，凭印象编

## 规则 2：注释极简

一行说清就够。禁止多行解释块、教学式长注释、设计论述——那是教案的事。对齐项目现有注释密度。

## 规则 3：不替用户做决定

用户说什么就做什么。不出「建议不做」「不如简化」的方案，不问「A 还是 B」（除非用户主动问）。

## 规则 4：不省略

完整实现，一次做完。没有豁免条款。
