# 三道闸门（机械步骤，不依赖记性）

## ① 复述闸（改文件前）

接到**修改/删除/新建文件**的指令，动文件前先输出一行复述：

```
我理解：<动作：删/改/新建> <哪些文件> <产出物是什么>
```

**必须复述的条件（满足任一）**：
- 指令存在两种以上合理理解（如"拆分"=移动还是复制）
- 影响超过一个文件
- 含删除动作或不可逆操作

满足条件 → 复述后等一个"对"字再动。改错字、修数字等小改**不复述**，直接干。

**按行号批量删除前，必须先打印删除范围的首尾若干行核对边界内容**——行号来自早先查询时不可信（文件可能已变），边界一步 `sed -n` 就能核对。2026-11-06 事故：删 27-453 行，453 附近已是正文而非详解块尾，行号抄自旧 grep，误删"第一个三角形"段与顶点着色器代码。

## ② 验证闸（每个动作后）

动作完成 ≠ 完成，**验证输出确认后才算完成**：

| 动作 | 验证 |
|------|------|
| 删文件/删内容 | ls / grep 确认没了、无新旧两份并存；**删除范围若靠行号，删后逐节核对正文完整性（代码块数量、关键段落是否还在）**——只查标题和残留标记不够 |
| 改内容 | grep 确认新内容在、旧内容无残留 |
| 渲染/构建 | 看报告零错误才宣布完成 |
| git 提交推送 | 看 log/输出确认结果 |

看都不看就宣布"完成/搞定" = 违规。验证失败的修正也算在本次动作内，不交半成品。

**根本原则：按风险验证，不按意图验证**。检查清单的来源不是"我担心什么"，而是"这个动作可能伤害什么"——删大量内容时头号风险是删多（核对边界 + 逐节确认正文还在），替换内容时是新旧并存，删除文件时是没删成。所有历史残留事故（rm 未生效、黑话残留、正文误删）的共同根因：检查只覆盖预期内的错误类型，事故全发生在预期之外。

## ③ 输出闸（回答问题前）

回答前自问：**"这个主题他接下来还会问什么？"**——连同相邻部分一次给全。

**触发判定**（满足任一即展开全量）：
- 问题属于本会话已聊过的主题（第 2 次触及）
- 我的答案里出现"以后会讲到/后面会撞上/到时候会看到"之类字眼——出现即就地展开，不留到"以后"

## 事故档案（这些闸门防的是什么）

- 复述闸：2026-11-06 "拆分干净文档"三次理解错（剪切/复制详解/仍安置自产内容），根因是隐含前提"我的内容必须活着"，从不把删除当候选理解
