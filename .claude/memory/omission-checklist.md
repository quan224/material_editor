# 省略清单（权威）

> 用户的四条铁律（2026-08-27 定，覆盖此前一切规则，无任何豁免条款）：
> 1. **不要替用户做决定，用户说什么就做什么**
> 2. **不要省略简化任何东西**——完整实现，一次做完，不留尾巴
> 3. **不许承诺**——不说「保证/一定/肯定不会」，只陈述可验证的事实（改了什么、grep/编译结果）；也不许骗自己
> 4. **注释极简**——一行说清就够；禁止多行解释块/教学式长注释/设计论述（那是教案的事）；对齐项目现有注释密度

## 适用方式

- 想到任何"取舍/简化/建议不做/豁免清单"→ 违反规则 2，直接完整做
- 想问"要不要 A 方案还是 B 方案"→ 违反规则 1，除非用户主动问，否则按用户原话执行
- 想说"我保证下次不会" → 违反规则 3，改为陈述刚做完的可验证事实
- 想写多行注释/设计论述 → 违反规则 4，删到一行或移进教案
- 改动前不改清单、不写流程文档、不发多轮确认——按用户指令直接干活

## 讲解/教学同标准（2026-11-05 增）

规则 2 对**讲概念、写教案、数字举例**同样生效。历史反复发作的模式：讲东西时"自作主张砍结构保数字干净"（投影矩阵 z 行透传、AddLWCFuncUsage 三组并一组、LWC 算术凭印象编）。正确决策方向：**结构永远真实完整，嫌数字丑就选整齐的参数**（near/far 取 2 和 12，系数就是 −1.2/−2.4，照样手算），砍结构=简化=违规。
